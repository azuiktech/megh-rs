## 2026-10-27
- A first OAuth login creates a personal tenant: `Tenants::create(name, owner)` makes the tenant and its owner membership (role `owner`, grants `["*"]`) in one transaction, and a user with no membership gets one named after their email. `/auth/me` returns `memberships` beside `user`. (PR #226, issue #225)
- Fix: the `:` (has) filter on a column that is not a list is a 400, not a 500. `ColumnMeta.is_array` is set by `#[derive(Table)]` for a `Vec<…>` field not stored as JSON; `megh::auth::filter::Has` gives each database's SQL (PostgreSQL `= ANY` for an array and `@>` for JSON, SQLite `json_each` for both); a `sqlite` feature turns on sqlx's SQLite support (PR #224, issue #222)
- Fix: emails ignore case (`users.email` and `connected_accounts.email` are `citext`; lookups cast their parameter), so a provider reporting another case links to the same user and password login takes any case; `set_password` and `update_profile` do not change a soft-deleted user; a `PUT` that changes a line's `invoice_id` is a 400, so a line never moves to another invoice. Changes the `email` column type in the schema shared with megh-go (PR #223, issue #221)

## 2026-10-26
- The availability search is a paged list: `POST /tenants/{tenant_id}/slots:search` (grant `slots:search`) replaces `appointments:available` and returns the `Page` every list returns (`items`, `next_page_token`), paged by `page_size` and `page_token` (AIP-158). A page covers start times in at most 7 days, never past `to`, and at most `page_size` slots, and loads only that stretch; `next_available_day` and its 180-day look-ahead are removed. Breaking for callers (PR #220, issue #219)
- Fix events: a closed stream leaves the broker (`publish` drops clients whose channel is closed); history backfill returns every allowed topic's history, each event once, oldest first; the bare pattern `*` matches exactly one segment (PR #218, issue #217)
- v7 UUIDs everywhere: `Uuid::now_v7()` in code and tests, `uuidv7()` in SQL defaults, the audit trigger and the reservation insert (PostgreSQL 18+); existing tables get the v7 default by `ALTER ... SET DEFAULT`; the `uuid` crate's `v4` feature is dropped (PR #216, issue #214)
- Fix security and tenant isolation: `authorizer` refuses a route whose `{tenant_id}` is not the token's `aud` or the member's tenant (RFC 9068 §4); `jwt_session` puts the decoded `AccessToken` into the request; replay and history send only topics the authorizer allowed, and no topic replays nothing; the events authorizer gets the caller's token (`Fn(Option<&AccessToken>, &Topic) -> bool`) and `POST /sub` adds topics only to a stream the caller opened; `POST /auth/{provider}/revoke` takes `account_id` and revokes only the signed-in user's own account (RFC 7009). Breaking: `Broker::with_authorizer`, `Broker::register`, the revoke body and the SDK's `revokeOAuth` (PR #215, issue #213)
- Fix data loss and corruption: an invoice or line write checks the draft and writes in one transaction that locks the invoice, so it and `:open` wait for each other (`crud` takes a pool or a transaction); a purge `before` a future time is refused; the token refresh holds no row lock or connection while the provider answers, the last update wins; event ids start at the current time in microseconds; invoice totals that overflow are `TooLarge`; `subscribe` refuses fewer than one seat; `ConnectedAccountRepo::encrypt_stored` encrypts tokens stored before encryption was on (PR #212, issue #211)
- Org renamed tenant, the partition every row belongs to: `Tenant`, `Tenants`, `TenantError`, `tenant_id`, tables `tenants`, `tenant_members`, `tenant_invites`, `tenant_configs`, routes `/tenants/{tenant_id}/...` and the token's audience. The migrations are compacted to one file per module (`0001_auth` to `0005_billing`) with no history; an existing database is renamed by hand. Breaking for callers and for megh-go (PR #210, issue #209)
- Org has a contact and an address: `Org::contact` (`email`, `home_phone`, `work_phone`, `mobile_phone`) and `Org::address`, the layout and types of booking's `Client`; migration `0020_org_contact_address.sql` adds the nullable columns (not in megh-go). Fields only until the org lifecycle (O2) can set them; `:open` still keeps `bill_to` as drafted (PR #208, issue #207)
- The CSRF check does not apply to a bearer token: `megh::auth::csrf_unless_bearer` skips the `CsrfLayer` for a request with `Authorization: Bearer` and applies it to any other, so a machine or a page on another site writes with its bearer token while cookie requests stay checked (`jwt_session` uses only the bearer token when one is present, so the header cannot carry a cookie request past the check); the example uses it on the API routes (PR #206, issue #205)

## 2026-10-25
- Client credentials for machines: `POST /auth/megh/token` takes `grant_type=client_credentials` (optional `scope`, which only narrows the grants) with `Authorization: Basic` and answers with the same JWT as `oauth2`'s `BasicTokenResponse` or an RFC 6749 §5.2 error; `UserRepo::register_machine(org_id, name, grants)` makes a machine (a user with provider `megh`, the client id as account id and email, one `machine` membership) and returns the secret once; `JwtSession::issue` is shared with the cookie renewal (PR #204, issue #203)
- The access token is read from `Authorization: Bearer` first, else the `jwt_token` cookie. A bearer token is only decoded (any failure is 401: no session, no renewal, no cookie set, no fallback to the cookie); a non-Bearer `Authorization` header is ignored; the OpenAPI description gets a `bearer` scheme next to `session` (PR #202, issue #201)
- Fix: a soft-deleted user (`deleted_at` set) is not found by `get_by_id`, `find_by_email` or `find_by_account`, cannot log in with a password, cannot sign in through a provider (the callback answers 403; `upsert` leaves the row as it is) and cannot renew a token from an old session (`Orgs::memberships` is empty for it) (PR #200, issue #199)
- CSRF on the login routes is stateless: `auth_router` and `basic_login_router` use `tower-http`'s `CsrfLayer` (`Sec-Fetch-Site` / `Origin`, no session or DB read) instead of the session token; `auth_router_with_csrf` and `basic_login_router_with_csrf` take a configured layer (trusted origins). Removed `GET /auth/csrf-token`, the `csrf` OpenAPI scheme, the `CsrfMiddleware`/`get_or_create_token`/`TOKEN_HEADER`/`TOKEN_KEY` re-exports and `axum-tower-sessions-csrf`; the UI SDK no longer fetches or sends a CSRF token (PR #198, issue #197)

## 2026-10-24
- Billing follows booking's layout: each entity's routes are in its own file (`tax.rs`, `invoice.rs` with `:open` and `:void`, `invoice_line.rs`, `payment.rs`), the router and OpenAPI are in `billing/mod.rs`, and the `routes` folder is gone; no names or behaviour change (PR #196, issue #195)
- Payments keep the invoice balance: recording, changing or deleting a payment refreshes the invoice in one transaction (`amount_paid` is the sum of `amount` less `refunded` over processing and succeeded payments, `balance_due` the total less that); a payment for an invoice that is not open, or that pays more than is owed, is a 409 and uses no number; the payment's number comes from the app's payment `Ids` when it is recorded and never changes; a refund is a PATCH of `refunded` (PR #192, issue #191)

## 2026-10-05
- Fix: the UI SDK drops its cached CSRF token when signing out, so the sign-in after a sign-out no longer fails once with 403; vitest added to the SDK (PR #75, issue #74)
- Fix: `megh::migrate` now runs migration 0008 (soft delete), which was missing from its list so `deleted_at` was never added and sign-in failed with "no column found for name: deleted_at`; it can also run again on a migrated database (0001 no longer recreates the renamed `org` tables, 0002 no longer indexes the dropped `users.subject`), as applications call it on every start (PR #73, issue #72)
- Soft delete for every entity: `Entity.deleted_at` and `TableEntity::soft_delete`, which marks the row and, in one transaction, everything a physical delete would remove through foreign keys declared `ON DELETE CASCADE` (read from the catalog, repeated to the leaves of a self-referencing tree; keys without `ON DELETE CASCADE` are not followed; a dependant table without `deleted_at` and `updated_at` fails the delete and changes nothing); `update` and `upsert` refuse deleted rows; `NOT_DELETED` is the condition reads add; migration 0008 adds `deleted_at` to the tables megh maps with `Table`; `update` and `upsert` now write `SET (cols) = ROW(values)`, which Postgres accepts for a single data column (PR #71, issue #70)
- Grants per resource level: `authorizer` now requires a grant for every resource level of the request path, from `request_grants(method, matched_template, uri_path)` (one grant per level in `resource:action:instance` form; the last level takes the HTTP action or a trailing `:verb` such as `/organizations/acme:activate` or `/organizations:batchCreate`, every ancestor needs `read`; a level without an id needs `*` or no instance; no level and no action implies another; prefixes such as `v1` produce no grant; under `Router::nest` the path comes from `OriginalUri`). This also fixes routes with a leading path parameter, which were always 403 because the resource was taken from the wrong segment. `Grant` is unchanged and `request_grant` stays for callers that want one grant (PR #68, issue #67; supersedes #66, issue #65)

## 2026-09-22
- Basic login route: `basic_login_router(state, path)` (opt-in, merge with `auth_router`), CSRF-protected; `Authorization: Basic` verified against `UserRepo::verify_password`, a uniform 401 `{"error":"invalid credentials"}` for a missing header or any wrong-credential reason, never creates an account; on success returns the user and their memberships and starts a session like the OAuth callback (PR #60, issue #30)
- Redacted secrets: `OAuthProviderConfig`, `ConnectedAccount` and `OAuth2Tokens` now hand-write `Debug` to print `"[redacted]"` for `client_secret`/`access_token`/`refresh_token` instead of deriving it, and no longer derive `Serialize`, so a stray `{:?}` or `Json(..)` of one fails to compile instead of leaking the secret at runtime (PR #59, issue #58)
- OAuth token encryption at rest: `Encryptor` (AES-256-GCM, `aes-gcm`), optional and off by default; `ConnectedAccountRepo::with_encryptor`, `Accounts::with_encryptor` and `MeghAuthState::with_token_encryptor` (the same key must be given to whichever of the three an app uses, since they read and write the same columns); a decrypt failure is a hard error, never silently swallowed or treated as already-plaintext (PR #57, issue #56)
- CSRF on every write path: `events_router`'s `POST /sub` is now behind `tower-http`'s stateless Origin/Sec-Fetch-Site check by default (`events_router_with_csrf` for a trusted cross-origin app); `megh::auth` re-exports `CsrfMiddleware`/`get_or_create_token`/`TOKEN_HEADER`/`TOKEN_KEY` so an app can protect its own session-backed routes with one `.layer(...)`; the UI SDK now fetches and sends the `x-csrf-token` header on every write (`signOut` was silently broken since F16) and re-fetches it after a 403 (PR #55, issue #54)
- OAuth callback hardening: the login sends a random `state` and an S256 PKCE challenge and keeps them in the session; the callback verifies `state` (constant time, one attempt per login, consumed even when wrong), sends the PKCE verifier, and rejects an email the provider has not verified; the result page posts to a configurable `web_origin` instead of `*` with its data in escaped HTML attributes; provider, database and session failures return fixed messages and are logged, and a failed `connected_accounts` save is an error; `oauth2` gets its `timing-resistant-secret-traits` feature; `MeghAuthState::with_web_origin`; the session cookie must be `SameSite=Lax` (PR #53, issue #22)
- Audit triggers: migration 0007 adds `audit_entries` (megh-go's schema) and the functions behind `megh::audit` (`AuditTrigger::on` / `dedicated` with overridable audit table, trigger name and key column, `Audit::install`, `history` and the transaction-scoped `Audit::actor`); one shared trigger function records old and new rows as JSON, every name is quoted by Postgres, and an existing trigger of the same name (for example megh-go's) is left alone (PR #52, issue #51)
- JWT access token in front of the session: `jwt_session` middleware (`JwtSession`, `AccessToken`, `JWT_COOKIE`) verifies a short-lived RFC 9068 token from the `jwt_token` cookie with `jsonwebtoken` 11 and gives its grants to `authorizer` without a database lookup; a missing or expired token is renewed from the `tower-sessions` session (the user's first membership), any other invalid token is rejected; the cookie is `HttpOnly`, `Secure` and `SameSite=Lax`, and `POST /auth/logout` clears it. Same claims as megh-go, so tokens verify in both stacks (PR #50, issue #49)
- `Subscriptions` (billing lifecycle ported from megh-go): plans (`create_plan`, `list_plans`, `plan`, `plan_by_sku`), `add_price`, `create_add_on`, `attach_plan_add_on`, and per organization `subscribe` (replaces the subscription, pads seats to the price's included seats, starts a trial and sets a one-month or one-year period), `change_seats`, `cancel(CancelWhen::Now | AtPeriodEnd)`, `attach_add_on`, `detach_add_on`, with `BillingError` (PR #48, issue #46)
- Billing entities and money: `megh::billing` row types for the megh-go billing tables (`Plan`, `PlanPrice`, `AddOn`, `PlanAddOn`, `Subscription`, `SubscriptionItem`, the status, interval and add-on type enums, `Money` accessors) and `megh::money` (`rusty-money`, `from_micros`, `to_micros`; prices stay `BIGINT` micros); `JsonText<T>` reads the JSON that megh-go keeps in text columns, NULL as empty (PR #47, issue #45)
- Password storage: `UserRepo::set_password` (bcrypt, portable with megh-go) and `verify_password`, which returns the `User` or a `PasswordError` saying why not (`UserNotFound`, `NoPassword`, `WrongPassword`, `Hash`, `Database`); megh-go's empty `password_hash` counts as no password, and a missing user or password still costs one bcrypt verification (PR #44, issue #29)
